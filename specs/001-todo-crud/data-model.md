# Phase 1 Data Model: Todo CRUD (Add, View, Toggle, Delete)

## Entity: Todo

Represents a single task the user is tracking (spec Key Entities: Todo).

| Field | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | Integer | yes (system-assigned) | autoincrement | Primary key; used as the REST resource identifier (`/api/tasks/:id`) |
| `title` | String | yes | — | Must be non-empty after trimming whitespace (FR-002); max length 200 characters (spec Assumptions) |
| `completed` | Boolean | yes | `false` | Toggled between `false`/`true` (FR-005, FR-006); never any other value |
| `priority` | Priority (enum: `LOW`, `MEDIUM`, `HIGH`) | yes | `MEDIUM` | Set at creation or changed later (FR-009, FR-010); exactly one of the three values, never a fourth |
| `createdAt` | DateTime | yes (system-assigned) | now() | Used to order the list consistently (spec Assumptions: "order they were created") |
| `updatedAt` | DateTime | yes (system-assigned) | now(), auto-updated | Set on every toggle/edit; not currently surfaced in the UI but kept for auditability and future use |

### Validation rules

- `title`: reject if empty or whitespace-only after trimming (FR-002); reject
  if longer than 200 characters (spec Assumptions edge case).
- `completed`: boolean only; no third state.
- `priority`: must be exactly `"LOW"`, `"MEDIUM"`, or `"HIGH"` (case-sensitive,
  spec Assumptions); when omitted at creation, defaults to `"MEDIUM"` (FR-009)
  rather than being rejected.

### State transitions

```
[created] --(add, title valid)--> completed = false, priority = given or MEDIUM
completed = false --(toggle)--> completed = true
completed = true  --(toggle)--> completed = false
priority = X --(set priority)--> priority = Y (any of LOW/MEDIUM/HIGH to any other)
completed = false | true --(delete)--> [removed]
```

Each Todo's state transitions are independent of every other Todo's (FR-006,
FR-007, FR-010: toggling, changing priority, or deleting one has no effect on
others).

### Relationships

None — Todo is a standalone entity with no relationships to other entities
in this feature.

### Ordering

The list is returned in `createdAt` ascending order (oldest first), matching
the spec's assumption of "the order they were created" with no
user-configurable sorting in this feature.

## Prisma schema

Matches the committed `prisma/schema.prisma`. Note: Prisma 7 no longer
allows a `url` in the `datasource` block (see research.md #3) — the
connection string lives in `prisma.config.ts`/`.env` instead. Native `enum`
is supported by the SQLite provider in Prisma 7.10.0 (verified via
`prisma validate`), so `Priority` is a real enum rather than a plain string.

```prisma
datasource db {
  provider = "sqlite"
}

enum Priority {
  LOW
  MEDIUM
  HIGH
}

model Todo {
  id        Int      @id @default(autoincrement())
  title     String
  completed Boolean  @default(false)
  priority  Priority @default(MEDIUM)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

Migration note: adding `priority` to an existing table used a full SQLite
table-rebuild (`CREATE new_Todo ... INSERT ... SELECT ... DROP ... RENAME`,
generated by `prisma migrate dev --name add_todo_priority`), since SQLite
can't `ALTER TABLE ADD COLUMN` with certain constraint changes directly.
Existing rows got `priority = 'MEDIUM'` automatically via the column
default in the `INSERT ... SELECT` — no manual backfill script was needed.
