# Implementation Plan: Todo CRUD (Add, View, Toggle, Delete)

## Summary

Users can add a todo (required title), view the full list, toggle a todo's
completion status, and delete a todo — all persisted locally. Technical
approach: expose the four operations as REST endpoints under Next.js App
Router route handlers (`app/api/tasks/route.ts`, `app/api/tasks/[id]/route.ts`),
backed by Prisma ORM against a local SQLite file (`dev.db`), with the existing
`app/page.tsx` UI calling those endpoints through a single typed client. No
separate server process or external service is required — everything runs
inside the existing Next.js dev/build process.

## Technical Context

**Language/Version**: TypeScript 5.x on Node.js (via Next.js 16.3.5)

**Primary Dependencies**: Next.js 16 (App Router, Route Handlers), React 19,
Prisma ORM + `@prisma/client`, Tailwind CSS 4 (existing UI styling)

**Storage**: Local SQLite file (`prisma/dev.db`), managed through Prisma
schema + migrations; `DATABASE_URL` read from environment with a local
default (see [research.md](./research.md))

**Testing**: Vitest (see [research.md](./research.md) for rationale) for
data-access/validation unit tests and API route contract tests

**Target Platform**: Local web app — browser UI served by the Next.js dev
server / a self-hosted `next build && next start`; no external hosting or
service signup required (per explicit user constraint)

**Project Type**: Single Next.js project (App Router serves as both UI and
API layer — no separate frontend/backend split)

**Performance Goals**: Matches spec Success Criteria — list/add/toggle/delete
actions reflected in the UI within 1 second; trivially achievable for a
single local user against a local SQLite file with no network hop

**Constraints**: Offline/local-only (no external service dependency); single
SQLite file as the only persistent store; no additional backend process

**Scale/Scope**: Single implicit user, expected on the order of tens to a
few hundred todos; no concurrency/multi-user requirements

**Structure Decision**: Single Next.js project (no separate frontend/backend
split) — the App Router's route handlers under `app/api/` act as the backend
within the same codebase as the UI in `app/`. Prisma schema and generated
migrations live at the repo root under `prisma/` since they're a project-wide
concern, not feature-scoped. Shared DB access, types, validation, and the API
client live under `lib/` so both route handlers and UI components import the
same definitions (Principle II/V).
